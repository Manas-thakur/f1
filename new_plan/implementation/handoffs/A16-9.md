# A16-9 — real-circuit UI: laboratory selector, circuit map, engineer and driver identity

Status: **complete for this scope, verified against the live control plane.**
Every value on screen is read from an HTTP response at the point of display.
No circuit list, hash, coordinate, tape or scenario id is compiled into the
bundle, and no route has a fallback: a route that fails renders an explicit
unavailable state that names the route and quotes the reason.

A16-8's catalogue routes landed while this work was in progress. The decoders
were rewritten against the real Pydantic response models in
`apps/api/afterlap_api/routes/catalog.py`, and the whole UI was then driven
against a running API — see **Live verification** below.

## Routes each view consumes

| View | Route | Used for |
|---|---|---|
| Lab → Circuit and conditions | `GET /api/v1/tracks` | one row per registered circuit: readiness rung, geometry provenance, short package hash, corridor quality, measured closure and length error, official length, licence text |
| Lab → Circuit map | `GET /api/v1/tracks/{id}/centreline?stride_m=5` | `x_m`/`y_m` from the compiled arrays, `package_hash`, `arrays_sha256`, `source_point_count`, `stride_m`, `length_m` |
| Lab → Conditions | `GET /api/v1/conditions` | `source`, `content_hash`, `rainfall_minutes`, `sample_count`, `duration_s`, `altitude_m`, `permission`, `available` + `unavailable_reason` |
| Lab → Scenario | `GET /api/v1/scenarios` | the id list (replaces the hardcoded array), plus each scenario's resolved circuit, readiness, package hash, `run_label` and `unavailable_reason` |
| Lab → Create session | `POST /api/v1/sessions` | sends `track_id` and `conditions_id` (already on the generated `CreateSessionRequest`) and reports back the manifest the **server** resolved |
| Engineer console | session snapshot / stream `SessionManifest` + `RuntimeCapabilities` | `track_id`, `event_id`, `track_readiness`, `track_package_hash`, `event_package_hash`, `geometry_provenance`, `conditions_id`, `conditions_hash`, `lateral_geometry`, capability `notes` |
| Driver display | same manifest + capabilities | circuit, rung, run label, corridor verdict |

The route paths are all under the single `/api/v1` prefix (`API_BASE` in
`src/api/client.ts`). No second prefix and no second wire format.

## What the UI refuses to claim, and how it shows unavailability

* **No validated real-track simulation, ever.** The ladder note under the
  selector states that no circuit reaches `simulation_eligible` and why
  (a surveyed corridor is required and location telemetry cannot supply one).
  `readinessTone()` never returns `verified` for any rung. Every place a
  circuit is named carries `real_circuit_synthetic_energy`: the lab panel
  header badge, the engineer header strip, the engineer circuit panel notice,
  and the driver context row.
* **Below `geometry_validated` is visibly unselectable.** The radio is
  `disabled` and `aria-describedby` the visible reason paragraph, so the reason
  is announced as well as drawn. The reason quotes measured evidence: the rung,
  the measured length error, and the validator's own `status …` note. It fails
  closed twice — the rung must be at or above `geometry_validated` **and** the
  catalogue's `simulation_ready` flag must be set; if the two disagree the
  circuit is refused and the text says the two disagree. An absent or
  unrecognised rung is also refused.
* **The corridor withdraws four fields by name.** `SessionCircuitPanel` reads
  the control plane's own `lateral_geometry` capability state (it re-reads the
  package the manifest's hash pins) and, when it is not `available`, lists
  *lateral position*, *side-by-side state*, *contact and wheel-to-wheel
  claims* and *usable track width* each against the word `unavailable`, with
  `CORRIDOR_UNKNOWN_REASON` above them. The fields are listed rather than
  omitted so a viewer can see the interface knows they exist and is declining
  to state them. The driver display shows `LATERAL POSITION — unavailable`
  (never `0`) with the same reason beneath it.
* **Attribution travels with the geometry.** `OPENF1_ATTRIBUTION` (CC BY-NC-SA
  4.0, non-commercial, attribution, share-alike, driven line not a surveyed
  centreline, openf1.org's own "unofficial") is rendered under the selector,
  under the map, and in the engineer circuit panel whenever provenance is
  `openf1_location_telemetry`. Each circuit row also prints its
  `licence_labels` verbatim, and each tape its `permission` verbatim.
* **Missing/erroring route → named unavailable state, no fallback.** Each of
  the four reads has its own `EmptyState` naming the exact route (including the
  query string) and quoting the failure — a typed `not_found`, a
  `ShapeMismatchError` naming the field that failed to decode, or a transport
  error. The circuit copy says "no circuit list is shipped in this bundle"; the
  map copy says "there is no traced outline and no image asset to fall back
  to". Verified live: with the API stopped, the panel renders *"The circuit
  catalogue is unavailable — missing artefact: circuit catalogue (GET
  /api/v1/tracks) — GET /api/v1/tracks failed: 502 Bad Gateway"* and draws
  nothing else.
* **`null` is never `0`.** `rainfall_minutes: null` renders "unavailable — the
  source carried no rainfall flag"; an unmeasured closure error renders "not
  measured"; an unretrieved official length renders "not retrieved"; an
  unverified one is marked "(unverified source)".
* **The map is real coordinates only.** One `<polyline>` built from the
  returned `x_m`/`y_m`, y negated once (SVG y grows down, ENU northing grows
  up), no smoothing and no client resampling. If the returned coordinates span
  no area in one axis it refuses to draw and says so. The short package hash
  and the `arrays_sha256` sit next to the drawing, with the drawn/compiled
  sample counts and the stride the server reported.

## Accessibility

* Both selectors are `<ul>`/`<label for>`/`<input type="radio">` inside an
  `aria-label`led list, so each option has a real label and the group is
  navigable with the arrow keys; disabled options are skipped by the browser's
  own radio-group behaviour. A disabled radio carries `aria-describedby`
  pointing at its visible reason. No `<select>` with disabled options was used,
  because a closed listbox cannot show the reason.
* The SVG is `role="img"` with an `aria-label` naming circuit, hash, point
  count, rung and that no corridor width is drawn. It is not focusable and adds
  no tab stop.
* `<details>`/`<summary>` for the validator evidence is native disclosure.
* No existing keyboard path was changed; axe passes on all three routes.

   chosen (a tape carries the venue altitude and an absolute wind heading) and
   prints a line telling the operator to check the tape's altitude and session
   against the circuit. If the binding should be enforced, the route needs the
   filter — a control-plane change, not a UI one.
4. **The Vite dev server on 5173 proxies `/api` only under `localhost`, not
   `127.0.0.1`** — the same IPv6/IPv4 quirk already documented in
   `vite.config.ts` for `preview.host`. Worth a comment on `server.proxy` too.

## Required integration actions

1. **Fold the four catalogue reads into `ApiClient`.**
   `src/api/trackCatalogue.ts` exists only because `src/api/client.ts` is owned
   by another agent — the same reason `features/lab/controlPlane.ts` exists.
   Methods to move: `listTracks`, `getCentreline`, `listConditions`,
   `listScenarios`. The decoders should move with them.
2. **Generate the catalogue response models into `packages/contracts`.**
   `TrackListResponse`, `TrackDetailResponse`, `CentrelineResponse`,
   `ConditionsListResponse` and `ScenarioListResponse` are route-local Pydantic
   models, so `packages/contracts/generated/contracts.ts` does not emit them
   and they are hand-declared in `trackCatalogue.ts`. Once generated, delete
   the hand-declared interfaces and keep only the decoders (the decoders are
   still wanted: they turn a shape change into a named unavailable state
   instead of a crash).
3. **Decide the `lint` script.** Either add ESLint (with
   `eslint-plugin-react-hooks`, which would have caught nothing here but is
   worth having) to `apps/web/package.json`, or remove the root `lint` alias so
   `pnpm lint` stops failing.
4. **`GET /api/v1/tracks/{id}` (detail) is unconsumed.** The selector shows the
   projection the list route already provides plus the validator `notes`. If a
   per-circuit source table, feature list or event-overlay review queue is
   wanted in the UI, that route already serves it and a panel can be added
   without touching the list path.
5. **No new tests were written**, per the completion-over-tests instruction.
   If A16-10 wants coverage, the natural units are `selectability()` and the
   four decoders (both pure), and one `CircuitConfiguration` render per route
   failure mode. `CircuitConfiguration`, `ScenarioPanel` and the selectors all
   already accept a `TrackCatalogueClient` / `client` prop as the test seam,
   and `TrackCatalogueClient` takes a `fetchImpl`, so
   `testUtils.makeFetch` works against it unchanged.
