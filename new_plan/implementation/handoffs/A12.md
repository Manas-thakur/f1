### 2.3 Selectors — `import { … } from '@/state/selectors'`

`selectSessionId, selectManifest, selectEstimate, selectRecommendation,
selectRuleContext, selectRevision, selectLastSequence, selectConnection,
selectResyncRequired, selectRejectedEnvelopeCount, selectTelemetrySeries,
selectSeriesByKey, selectTelemetryFreshAtS, selectDataAgeS,
selectQualitySummary, selectTimeSensitiveActionsEnabled,
selectTimeSensitiveDisabledReason, selectIsRequestPending,
selectAnyRequestPending, selectRequestError, selectHasConflict, selectView,
selectCursor, selectInspector, selectDensity, selectMotion, toStreamSlice`

**Reference stability:** every selector above returns a stable reference for a
given store state, so any of them may be passed straight to
`useSessionStore(...)`. The three that derive an object
(`selectQualitySummary`, `selectCursor`, `selectTelemetrySeries`) are memoised
on the slice they read via a `WeakMap`, so a new reference appears only when
that slice really changes. This was originally a documented hazard — an
unmemoised `selectQualitySummary` rendered the session strip forever during the
build — and is now enforced by `state/selectors.test.ts` rather than left to a
comment. The session strip uses `selectQualitySummary` directly as the proof.

Gate every time-sensitive control on
`selectTimeSensitiveActionsEnabled` and show
`selectTimeSensitiveDisabledReason` as the `disabledReason`.

### 2.4 Reducer — `import { reduceStream, applySnapshot, reduceAll, telemetryKey } from '@/state/streamReducer'`

`reduceStream(slice: StreamSlice, envelope: StreamEnvelope): StreamSlice`, pure.
Implemented rules, in evaluation order:

1. envelope for another `session_id` -> ignored, counted `wrong_session`;
   a delta may never bind a session, only a snapshot may;
2. `snapshot` -> atomic replace of session state **and** `last_sequence`;
   telemetry is cleared so no pre-resync sample survives; applied regardless of
   sequence;
3. `resync_required` -> honoured **before** the sequence check (a gap in the
   message announcing a gap must not suppress it); pauses delta application;
4. `heartbeat` -> updates `lastHeartbeatAtS` only. Never touches
   `telemetryFreshAtS`, never moves `sessionTimeS`, never triggers a resync.
   It advances `lastSequence` only when it is exactly the next sequence, which
   is correct whether or not the server sequences heartbeats;
5. deltas while `applyingDeltas === false` -> dropped, counted `deltas_paused`;
6. sequence: `to <= lastSequence` -> `duplicate_sequence` (no resync);
   `from !== lastSequence + 1` -> **resync**. `telemetry_view` uses
   `coalesced_from_sequence` / `coalesced_to_sequence` when present;
7. `estimate_updated` -> applied only at `revision === current + 1`;
   `<= current` is `stale_estimate_revision`; a skip is
   `estimate_revision_skip` and triggers a resync;
8. `recommendation_updated` -> matching session, and strictly newer:
   same id needs `revision > current.revision`; a different id needs
   `state_revision >= current.state_revision`;
9. `quality_changed` -> merges channel quality and the message; the derived
   selectors disable time-sensitive actions immediately;
10. `rule_context_changed` -> replaces the context and, when the current
    recommendation id is in `invalidated_recommendation_ids`, sets its status to
    `invalidated` (server-driven, not optimistic);
11. `execution_observed`, `experiment_progress`, `telemetry_view` -> appended /
    merged; only `telemetry_view` sets `telemetryFreshAtS`.

The reducer never sets a recommendation status from a local interaction.

### 2.5 Chart contract — `import { ChartFrame, type ChartSeries, fromTelemetrySeries, decimateMinMax, interpolateAt, summariseSeries } from '@/components'`

```ts
interface ChartSeries {
  id, channel, label, carId?, unit, provenance,
  xCoordinate: 'progress_m' | 'session_time_s',
  x: readonly number[], y: readonly (number|null)[],
  yLow?, yHigh?, quantileDefinition?,   // a band without a definition is a bug
  sampleTimestampsS?, nativeResolution, sampleCount, decimated,
  events?: EventMarker[],               // {kind,id,x,label,preserveExactly?}
  role: 'selected' | 'reference' | 'context',
}
```

`ChartFrame` props: `{ title, subtitle?, series, height?, cursor?,
onCursorChange?, maxPoints?, emptyArtefact?, emptyAction?, actions? }`.

It provides, and A09/A10/A11 must not reimplement:

- min/max envelope decimation that keeps both extrema of every bucket, both
  span bounds, every `preserveX` (checkpoints, rule transitions) and a
  representative gap;
- a labelled `<input type=range>` cursor with `aria-valuetext`, driving the same
  x position across panels — pass `useSessionStore` `view.cursorValue` /
  `setCursor` to share one cursor;
- per-series readouts at the cursor marked `(sample)` or `(interpolated)`;
- a `<details>` numeric summary table with min/max/mean/last in display units,
  the x range, the original sampling resolution, whether it was decimated, gap
  counts and the quantile definition;
- an event-marker list, de-duplicated across series;
- reference series drawn dashed **and** in the reference hue;
- **display-unit conversion before plotting**, one y scale and one labelled
  axis per display unit (left, then right, alternating), and an x scale pinned
  to `time: false` so a physical coordinate is never formatted as a clock time.
  Give a panel two series in different units and it gets two labelled axes for
  free; do not pre-convert values yourself, pass SI and let the frame do it.

`fromTelemetrySeries(series, { role, label, events })` adapts a transport
`TelemetrySeries` from the store.

### 4.1 Chart axis defects, and why the earlier suite missed them

The coordinator found two rendering defects in `ChartFrame` by looking at the
painted chart in real Chrome. Neither could fail: **154 unit tests and 48
browser tests, and not one of them read the canvas.** uPlot paints its axis
ticks with `fillText`, so no DOM query can see them, and every assertion I had
written was about the DOM or about my own formatters.

| Defect | What a reader saw | Cause | Fix |
|---|---|---|---|
| x axis rendered as wall-clock time | `5:30am … 6:55am` and `1/1/70` under an axis captioned "distance (m)" | uPlot's x scale defaults to `time: true`, so progress in metres was formatted as a Unix timestamp | `scales: { x: { time: false } }`, plus an explicit `values` formatter keyed on the series' `x_coordinate`, plus a painted axis `label` carrying the unit |
| y axis clipped and contradicting the legend | `)00,000` with the leading digit cut off; six-digit raw W/J against a legend reading kW and MJ; the kW trace flattened onto the baseline | values handed to uPlot in raw SI, one shared linear y scale for units six orders of magnitude apart, and uPlot's fixed 50px default axis width | convert through the channel registry before plotting; one scale and one labelled axis per display unit (left/right); `size` computed from the widest label actually produced |

New module `src/components/charts/axes.ts` holds the grouping and the
formatters so they are unit-testable; `e2e/canvasPaint.ts` patches
`CanvasRenderingContext2D.fillText` via `page.addInitScript` and records every
painted string with its box, in device pixels.

**The regression tests were falsified before being accepted.** I restored the
original axis configuration exactly (default axes, no `scales`, raw SI data, no
`values`, no `size`, no per-series scale), rebuilt, and ran the new spec:
**10 of 11 tests failed**, with the reported symptoms verbatim:

```
Error: uPlot formatted a distance axis as a wall-clock time; set scales.x.time = false
  Received: ["5:30am", "1/1/70", "5:35am", "5:40am", "5:45am", "5:50am", …]   (40 entries)

Error: y tick magnitudes ["0","1,000,000","2,000,000","3,000,000","4,000,000", …]
       look like raw SI, not display units
  Expected: < 1000   Received: 4000000

Error: a label was painted outside the canvas; reserve axis size from the widest tick
  Received: [{ text: "1,000,000", left: -11, right: 39, canvasWidth: 1114 }, …]
```

`left: -11` is the `)00,000` clipping, measured. The one test that still passed
against the broken build asserts the DOM caption, which is a mirror of the axes
rather than a canvas assertion — noted so nobody mistakes it for coverage of the
paint.

With the fix restored, all 11 pass. A first attempt at this falsification was
too crude — it broke the axis outright so the tests failed with "no ticks
painted" rather than reproducing the defect. That result was discarded and the
experiment redone against the true original configuration.

**Standing limitation:** these assertions cover tick text, magnitude and
placement. They do not compare pixels, so a wrong trace colour, a wrong line
shape or an inverted series would still pass. Anything about the *shape* of a
plot still needs a human or an image comparison.

## 5. Design decisions worth knowing

- Tokens are ported from `12_design/mockups/tokens.css`. Every colour answers
  selection (`--accent` blue), series identity (`--series-*`, mirroring
  `registry.plot_colour_token`, with a `-well` lighter shade of the same hue for
  the dark trace area) or status (`--good`/`--bad`/`--warn`). Fixture and
  proposed states use the neutral badge.
- Spacing is 4/8/12/16/24/32/48/64. Body 14px, secondary 12px, micro 11px,
  operational headings 24–29px. `font-variant-numeric: tabular-nums` on every
  changing value.
- Font stack is Segoe UI/Arial and Consolas/Courier New. There is no network
  font request anywhere in the app, essential or otherwise.
- The module rail is plain named modules with a selected inset edge. No
  numbering, asserted by a test.
- Reduced motion: `prefers-reduced-motion` plus an explicit `/settings` override
  written to `:root[data-motion="reduce"]`; both zero out durations and
  transitions.
- Density writes `:root[data-density="compact"]`, which changes spacing tokens
  only — never type sizes.
- No gradient fields, no glowing borders, no animated fake telemetry, no
  decorative car renders, no bento grids, no invented confidence, no decorative
  numbering, no slogans. Landing specimen data is a deterministic authored
  fixture, labelled as one, with no clock and no animation.
- The specimen deliberately includes a null quantity (rival stored energy) so
  the "unavailable, not zero" rule is visible on the product page itself.

## 6. Known limitations

1. **Seven routes are placeholders.** They render a real `EmptyState` naming the
   owning agent and the missing artefact. They are not stubs pretending to work.
2. **No backend.** Every REST call in the e2e suite is mocked by route
   interception in `e2e/mockApi.ts`. `SessionStream` is unit-tested against an
   injected fake socket; it has never spoken to a real server. First integration
   with A08 should re-verify: the `/ws` path (`basePath` defaults to `/ws/v1`,
   while `01_contracts/API.md` documents `/api/v1/sessions/{id}/stream` — see
   item 1 of §7), auth on the socket, and reconnect behaviour under a real
   bounded replay buffer.
3. **uPlot is not exercised in unit tests.** jsdom has no 2D canvas;
   `ChartFrame` probes `getContext('2d')` and falls back to its numeric summary.
   The canvas path is covered only by the Playwright suite. That suite now reads
   the painted text (see §4.1), but it still compares no pixels: a wrong series
   colour, a wrong line shape or an inverted trace would pass. Treat plot
   *shape* as unverified.
4. **Beyond two units per panel is untested in a browser.** `unitGroupsFor`
   alternates left/right for any number of unit groups and is unit-tested with
   three, but only the two-axis case has been looked at in Chromium. A panel
   mixing three or more units may crowd its axes.
5. `formatChannelValue` for an *unregistered* channel prints the raw SI value at
   3 decimals with whatever unit the caller supplies. That is deliberate — no
   guessed conversion — but it means a channel added to the Python registry and
   not mirrored here renders unconverted. `channels.test.ts` fails loudly when
   that happens.
6. Density and motion preferences live in memory for the session only. They are
   not persisted to `localStorage` and not sent to the server.
7. The Radix Popover dependency is installed and pinned but not yet used by any
   primitive; it is there for A09/A10 inspectors.
8. `--series-accel`, `--series-lateral`, `--series-progress` and the rest of the
   registry hues have been checked for distinctness by eye, not by a measured
   colour-difference test. Reference series are additionally dashed so the
   distinction does not depend on hue.
9. The bundle is 417 kB raw / 138 kB gzipped, of which the generated
   `schemas.json` is the largest single contributor. It is required for runtime
   envelope validation. If this matters later, split it into a lazily-loaded
   chunk fetched when a session stream opens.

## 7. Required integration actions

1. **Stream path: settled.** The endpoint is
   `/api/v1/sessions/{id}/stream?after_sequence=N` on the same origin, which the
   existing `/api` dev proxy and the production nginx rule already cover.
   `SessionStream` defaults to `STREAM_BASE_PATH = '/api/v1'`, exported from
   `src/api/stream.ts`, and it remains a constructor argument so a deployment
   can move it without forking the client. `/ws` stays reserved and unused; the
   Vite proxy entry for it is left in place and harmless.
2. **A09/A10/A11:** create only your feature directory and swap the one element
   in `src/app/routes.tsx`. Do not add a second store, a second chart-event
   protocol, or local restyles of the primitives. If a primitive is missing a
   state you need, extend it here rather than shadowing it.
3. **Selectors are safe to pass to `useSessionStore` directly.** The derived
   ones are memoised on the slice they read and `state/selectors.test.ts`
   enforces it. If you add a selector that derives a new object, memoise it the
   same way — do not leave it to the caller.
4. Regenerate the test fixtures whenever the contract revision moves:
   ```
   uv run --project new_plan/implementation python -c "..."   # see below
   ```
   `src/test/contractFixtures.ts` and `src/test/pythonRegistry.ts` are generated
   from `afterlap_contracts.fixtures` and `afterlap_contracts.registry`
   respectively, with `model_dump(mode='json')` and a
   `as unknown as <ContractType>` cast. They are committed so the web tests do
   not need a Python runtime.
5. CI must run `pnpm --filter @afterlap/web e2e:install` before `test:e2e`.
6. When the API lands, replace `e2e/mockApi.ts` route interception on at least
   one spec with a real backend fixture so the contract is exercised end to end.

## 8. What this does **not** establish

The shell renders, the reducer obeys its rules, and the four owned routes are
accessible at seven widths. That is all. No decision quality, no simulator
behaviour, no rule coverage and no model claim is supported by anything in this
module. The product pages say so on screen, and the synthetic-data notice is
asserted by test on every route.
