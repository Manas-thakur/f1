## Public interfaces

```python
from afterlap_core.simulation import Simulator, DriverAction, load_bundle

sim = Simulator().reset(manifest_or_scenario, seed=None)   # id | ScenarioConfig | ScenarioBundle
report = sim.step(driver_actions: dict[str, DriverAction] | None, dt_s: float) -> StepReport
snapshot = sim.snapshot() -> dict            # plain data, deep-copied
sim.restore(snapshot)                        # refuses a snapshot from another bundle
obs = sim.observe(sensor_config=None, car_id=None) -> dict[str, Observation]
```

Supporting helpers: `sim.detect_geometry_events()`, `sim.energy_close_errors()`,
`sim.passes_of_kind(kind)`, `sim.world` (private truth — exposed for tests and
for the branching helper only).

`StepReport` carries `events`, `passes`, `saturation_events`, `checkpoints`,
`policy_actions`, `profile_downgrades`, `envelope_exceedances`, `substeps`.

Branching:

```python
from afterlap_core.simulation import Treatment, run_branch, run_paired, capture_complete_state
result = run_branch(bundle, snapshot, Treatment(id=..., controller=fn),
                    horizon_s=..., dt_s=..., checkpoint_ids=(...,))
result.outcomes            # tuple[afterlap_contracts.OutcomeRecord, ...]
result.truncated           # True when any checkpoint was not reached
result.rival_actions       # per-step opponent decisions, for paired comparison
```

Any car absent from the `driver_actions` mapping is driven by its configured
opponent policy, which is called with **that car's own observation**.

## Model and numerical choices

**Integrator: explicit midpoint (RK2) on float64** for progress, speed and
lateral offset. The predictor at the start of the step only locates the
midpoint; the corrector's electrical plan is the one committed, so the
electrical demand is second-order too. The plan is saturated once against the
whole step from the start-of-step stored energy, which is what makes the battery
ledger close to float noise rather than to a truncation error.

**Thermal state** uses the exact solution of `C_th dT/dt = P_loss - h(T-T_amb)`,
so it is unconditionally stable and independent of dt for a constant loss.

**Step splitting.** A step is split at the interpolated crossing time
(`timebase.crossing_time`) of a checkpoint or the timing line, and at the apply
time of a delayed driver action. Events are pushed into the coordinator's
`EventQueue` with `EventPriority.PHYSICAL_LINE_EVENT` and drained in contract
order. Splitting stops below 1e-4 s, which bounds the number of sub-steps;
observed average is 1.00 sub-steps/step with a maximum of 2.

**Driver model.** A backward braking-point pass over a 0–400 m preview grid
(4 m near, 20 m far) computes the highest speed that still fits every corner,
using the deceleration the friction ellipse actually leaves at each grid point.
Above the target the driver brakes at the envelope; below it a first-order
governor (τ = 0.6 s) sets throttle. Two calibration constants:
`_CORNER_GRIP_SHARE = 0.95` (the lateral share the driver plans a corner
around) and `_BRAKING_SAFETY_MARGIN = 0.97`. Both are documented driver-model
assumptions, not tyre physics; without the grip reserve the planned apex leaves
zero braking authority and a 1 m/s overshoot becomes unrecoverable.

**Pass detection.** Longitudinal condition is nose-to-tail separation
(`0.5*(L_a+L_b)`, 5.6 m for the shipped car); physical clearance is decided by
the separating-axis footprint test. `attempted_pass`, `completed_pass`,
`retained_pass`/`lost_pass` and `blocked_by_contact` are recorded separately.
Hysteresis is the `[-clearance, +clearance]` band plus an `armed` flag, so a car
that has just been passed does not immediately register an attempt of its own.

**Geometry frame.** Pairwise footprints are built in a local Cartesian frame
anchored at the rear car's arc length, never in a global map frame, so the lap
wrap and any map closure error cannot corrupt contact detection.

15.7 GB RAM, CPython 3.12.14 (AMD64), numpy 2.5.3, scipy 1.18.1, pydantic

The third is slower because both cars spend the run at low speed in the tight

hotspot to vectorise or move to Numba; the reference implementation must be kept
for the numerical tests, as the plan requires.

## Known limitations

1. **Not calibrated.** No parameter is fitted to any measurement. Every fixture
   is `synthetic_assumption` and the loader will fail the provenance test if
   anything claims otherwise. This is not a digital twin and no fidelity claim
   is made.
2. **Reduced lateral model.** A first-order line-tracking model with a heading
   error derived from lateral rate — not a bicycle model with slip angles.
   There is no understeer escape, so if lateral demand ever exceeded the tyre
   envelope the model could not resolve it; that state is *recorded* in
   `StepReport.envelope_exceedances` as `unsupported_by_reduced_model` rather
   than clipped. No fixture currently produces one.
3. **No wake/slipstream model.** The spec permits one through documented
   calibrated coefficients; none exists, so drag is unaffected by proximity.
   This makes tow-assisted overtakes harder than reality.
4. **Regulatory admissibility is a placeholder.** `_update_legal_profiles` only
   enforces the physical battery window and the thermal derate. The rules module
   (A04) owns real eligibility, power curves and recharge allowances; the
   simulator does not duplicate them and does not read a rule pack yet. This is
   the main integration point.
5. **Flags are static.** `RaceState.flags` is initialised to green and nothing
   changes it. Safety-car and VSC events are wired through the event queue's
   `SAFETY_OR_RULE_INVALIDATION` priority but no producer exists yet.
6. **Cross-platform reproducibility is not claimed.** Determinism is asserted as
   bit-identical on this platform and build, as the clock contract scopes it.
7. **Wind and grip disturbances are keyed but not driven.** `KeyedRandom`
   streams exist and sensor noise uses them; there is no wind or track-evolution
   producer yet. Adding one must key by physical time so paired branches keep
   sharing disturbances.
8. **Contact resolution is detection only.** An overlap blocks a pass and is
   recorded; it does not produce a collision response, damage or an off-track
   excursion. Reporting "unsupported" was chosen over inventing a probability.
9. **`_envelope_speed` is the performance bottleneck** (see above).

## Fixture provenance

Both track centrelines are synthetic sketches: a curvature/grade/width/grip
profile chosen by hand, then the corner curvatures solved numerically (SciPy
`fsolve`) so the integrated centreline closes. Measured closure: `test-loop`
0.004 m position, 2e-5 rad heading; `test-oval` 0.033 m, 5e-5 rad. Closure
matters only for drawing a map — the physics runs in an arc-length frame and
pairwise geometry in a local frame — and `TrackGeometry.closure_residual_m` /
`closure_heading_residual_rad` expose the number so a renderer can state its own
precision. `lateral_geometry_surveyed` is `False` and
`geometry_provenance` is `synthetic_sketch` on both, and a validator refuses a
synthetic track that claims surveyed geometry.

The car is a plausible-order sketch of a 2026-style energy-recovery single
seater (798 kg, CdA 1.20 m², ClA 4.00 m², 400 kW ICE map, 350 kW deploy and
harvest ceilings, 0–4 MJ window, η_discharge 0.95, η_charge 0.94, lumped
80 kJ/K and 900 W/K thermal model). It is **not** a measured Formula 1 car and
the YAML says so in a header comment as well as in every parameter's
verification field.

`two-straight-counterattack.yaml` reproduces `03_simulation/scenario.example.json`
exactly — track `test-loop` (5 200 m), checkpoints at 2 100 m and 3 500 m, own
speed 75 m/s, own energy 2.4 MJ, rival energy 2.8 MJ, gap ahead 0.65 s,
observation delay 0.15 s, rival energy hidden, seed 42, rule pack
`synthetic-pack-v1-unreviewed` — and a test asserts each of those values. The
declared `gap_ahead_s` is validated against the initial progress and speed, so
the human-readable fixture cannot drift from what the simulator starts from.

The YAML files were emitted by a generator script kept in the session scratchpad
(not in the repository); the YAML documents themselves are the deliverable and
are the reviewed artefact.

## Required integration actions

1. **A04 (rules):** the simulator needs a hook to consult the rule pack for
   admissible profiles, deployment/recovery ceilings and the per-lap recharge
   allowance. Suggested shape: pass a `RuleContext` provider into
   `Simulator.reset` and call it in `_update_legal_profiles`, replacing the
   placeholder. The CU-K ledger already integrates DC-bus energy at the bus the
   rule pack names (`recharge_measurement_bus`), and `reset_lap_counters()` is
   already wired to the timing line.
2. **A05 (estimation):** `Observation` is the only input path; it exposes the
   own-car channels in `observation.OWN_CHANNELS` and the rival channels in
   `RIVAL_CHANNELS`, with `battery_energy_j` gated on
   `energy_channel_available` and rival energy gated on `expose_rival_energy`.
   The `loop-no-energy-channel` scenario is the held-out case with no own-energy
   measurement.
3. **A06/A07 (planning, RL):** use `run_branch`/`run_paired` for paired
   comparison; they already emit `afterlap_contracts.OutcomeRecord` with an
   explicit `incomplete_reason` when the horizon truncates. Do not compare a
   truncated branch at an earlier checkpoint — `BranchResult.complete_outcomes`
   filters them.
4. **A08 (session runtime):** `WorldState` has no wire schema and must never be
   serialised into a contract object. Snapshots are plain dicts for branching
   and restore only; publish `OutcomeRecord`/`Observation`-derived data instead.
5. **A13 (evaluation):** the spec asks for an independent higher-resolution
   evaluator and an independent energy-ledger checker. `EnergyLedger.close_error()`
   is the simulator's *own* audit, not an independent one; a genuinely separate
   checker still needs to be written, and I have not written one.
