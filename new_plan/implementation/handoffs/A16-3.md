## validate_track — what it checks and how it decides

All quantities are recomputed from `x_m, y_m, z_m` in `centreline.npz`; the compiler's numbers are only compared against, never reused.

| check | method | tolerance | on fail |
|---|---|---|---|
| `arrays_sha256` | sha256 of the file vs `geometry.arrays_sha256` | exact | rejected |
| `no_nan` | all seven required arrays finite | — | rejected |
| `s_monotonic_spacing` | `s[0]==0`, `diff(s)` all `== sample_spacing_m` within 1e-6, `s[-1] < length` | 1e-6 m | rejected |
| `yaw_tangent` | `atan2(dy, dx)` via `np.gradient` vs `yaw_rad` | 0.05 rad max | rejected |
| `curvature_yaw` | `gradient(unwrap(yaw))/ds` vs `curvature_1pm` | 0.005 1/m max | rejected |
| `curvature_bounded` | `max|kappa|` | 1/6 1/m | rejected |
| `grade_bounded` | `max|grade|` | 0.25 | rejected |
| `direction` | shoelace signed area sign vs declared (`mixed` -> unknown) | — | rejected |
| `closure` | last sample advanced along its chord to `s = L`, distance to sample 0 | 0.5 m | discovered |
| `length_declared` | 3-D chord sum + closing chord vs `length_m` in the npz | 0.5 % | discovered |
| `length_official` | same vs manifest `official_length_m.value` (else `validation.official_length_m`) | 0.5 % (manifest `length_tolerance_fraction` overrides) | discovered |
| `sources_hashed` | at least one source with sha256; unhashed ones noted | — | discovered |
| `corridor` | quality not unknown **and** finite half-widths | — | unknown gates eligibility; a quality claim without finite widths is rejected |
| `event_overlay_confirmed` | any `events/<id>.json` with `review_status == confirmed` (or one already embedded) | — | unknown -> stays geometry_validated |
| `conditions_calibrated` | `conditions/calibration.json` with `status: calibrated` and non-empty `source_sessions` | — | unknown -> stays event_rules_validated |

Ladder: geometry checks all pass -> `geometry_validated`; + confirmed overlay (embedded into `package.event_overlay`) -> `event_rules_validated`; + calibration report -> `condition_calibrated`; + corridor -> `simulation_eligible`. The seam is judged by `closure` only; consistency checks use one-sided differences at the ends so an open loop reads as a closure failure, not as an integrity failure.

Loading refuses a `package.json` whose stored hash does not match (tampered) and, through the `TrackPackage` validator, any status above its evidence. An unhashed compiler output is accepted and hashed on write. Re-validation is idempotent (the package's `ValidationReport` carries no timestamps; the sidecar report does not either).

## Review queue behaviour

`review_overlay(track, event, reviewer, "confirm"|"reject", paths)`: `unreviewed -> one_reviewer -> confirmed` only with two **distinct** names (whitespace-stripped); the same name again is logged as `no_change`; `reject -> recalled`, after which review is refused until re-ingest. Every decision is appended to `events/<event>.reviews.jsonl` with timestamp, reviewer, document sha and ruleset hash; the overlay file carries `reviewers`. Re-ingesting a document with a different sha moves the prior overlay to `events/<event>.superseded-<sha12>.json` and restarts at `unreviewed`. **No review was recorded by me.** The coordinator decides whether a human review is entered.
