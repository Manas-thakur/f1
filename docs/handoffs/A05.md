## 2. Public interfaces

```python
from afterlap_core.estimation import (
    EstimationContext, EstimatorState, create_state,
    update, update_state, predict, sample_scenarios,
)

state = create_state(session_id=..., car_id=..., seed=...)          # loads both manifests
estimate: StateEstimate = update(events, state, context)            # advances `state` in place
new_state, estimate = update_state(events, state, context)          # pure form; `state` untouched
projected: StateEstimate = predict(estimate, target_time_s, state=state)
ensemble = sample_scenarios(state.rivals[car_id], count, seed, horizon_s=..., step_s=...)
```

* `update(events, prior, context) -> StateEstimate` — `prior` is an
  `EstimatorState` (covariance, particles, RNG streams, slot assignments, mode
  memory, observation history). It is **advanced in place**; use `update_state`
  when a replay needs to branch without disturbing the trunk.
* `predict(estimate, target_time_s, *, state=None) -> StateEstimate` — `cutoff_s`
  does not move; only `created_at_s` advances. See §7 for the `state=None` caveat.
* `EstimatorState.snapshot()` / `.restore()` returns a JSON-serialisable dict
  suitable for `afterlap_core.data.replay.EstimatorSnapshot.payload`.

Rejected post-cutoff observations are on `EstimatorState.rejected`
(`RejectedObservation`), deliberately **not** on the published estimate — see §6.

## 3. Noise values and how they were chosen

### Own-car EKF (`configs/estimation/own-car-ekf-v1.yaml`)

State `x = [progress_m, speed_mps, acceleration_mps2, battery_energy_j]`, float64.

| Parameter | Value | Basis |
|---|---|---|
| `acceleration_time_constant_s` | 0.8 s | Hand-set. How fast the filter forgets a throttle input. |
| `drag_per_m` | 9.75e-4 1/m | `0.5·rho·CdA/m` with rho=1.2, CdA=1.3 m², m=800 kg → 5.5 m/s² of drag at 75 m/s. This term is the only state nonlinearity. |
| `process_jerk_psd` | 25 m²/s⁵ | Tuned on the calibration harness until mean NIS sat near 1.0. Gives sigma_a ≈ 1.1 m/s² over a 50 ms tick, 5 m/s² over a second. |
| `harvest_efficiency` | 0.92 | Hand-set. Applied on the harvest leg only, so the DC-bus and battery ledgers stay separate. |
| `power_model_sigma_w` | 4 kW | Tuned; contributes `(sigma·dt)²` to the energy process variance. |
| `unobserved_gap_sigma_w` | 90 kW | Hand-set. Multiplies `integration_gap_s` from `afterlap_core.data.quality`, so a power dropout widens energy instead of integrating to zero. |
| `speed_sigma_mps` | 0.20 m/s | Tuned. Generator emits 0.20; 0.878 measured coverage says it is not optimistic. |
| `progress_sigma_m` | 0.60 m | Tuned. Generator emits 0.60. |
| `energy_sigma_j` | 15 kJ | Hand-set, matches the contract fixture. |
| `nis_alarm_threshold` | 9.0 | 3-sigma normalised innovation. Fires `EstimateQuality.residual_alarm`; it never retrains anything. |
| `max_prediction_step_s` | 0.25 s | Longest single linearisation interval; longer elapsed times are subdivided. |

Tuning method: the calibration harness in `tests/estimation/test_calibration.py`
runs the estimator over 12 scenarios, pairs each posterior with hidden truth read
*after* publication, and reports mean NIS and interval coverage. `process_jerk_psd`,
`speed_sigma_mps` and `progress_sigma_m` were adjusted until mean NIS approached
1.0 and 90 % coverage approached 0.90. Six of the twelve scenarios add a
proportional driver term the filter does not model, so the numbers are not purely
self-fulfilling — but see the honesty caveat in §5.

Clock uncertainty enters in two places, both widening only:
`Q[progress] += (v·sigma_c)²`, `Q[speed] += (a·sigma_c)²` on prediction, and
`R[progress] += (v·sigma_c)²`, `R[speed] += (a·sigma_c)²` on correction.

### Rival filter (`configs/estimation/rival-modes-v1.yaml`)

| Parameter | Value | Basis |
|---|---|---|
| `particle_count` | 128 | From `MODEL_AND_DATA_SPEC`; an initial setting to profile. |
| `ess_resample_fraction` | 0.5 | From the spec: resample when ESS < N/2. |
| `mode_weight_floor` | 0.02 | Hand-set. Implemented as uniform mixing into each particle's mode belief. |
| `min_particles_per_mode` | 2 | Scenario diversity, not the posterior. |
| `mode_time_constant_s` | 6 s | Elapsed time over which the transition matrix applies in full. |
| `base_speed_gain_mps` | conserve −1.20, normal 0, **attack 1.55, defend 1.55** | Hand-set. Attack and defend are *identical* at zero pressure on purpose (§4). |
| `pressure_speed_gain_mps` | attack +0.25, defend +0.55 | The only thing that separates them, and only weakly. |
| `base_power_w` | conserve −40 kW, normal 0, attack 165 kW, defend 165 kW | Hand-set. |
| `deploy_reference_energy_j` | 0.9 MJ | The pace gain saturates above this; watching a rival deploy identifies "not nearly empty" and nothing more. |
| `energy_process_sigma_w` | 90 kW | Tuned (see §5); within-mode deployment uncertainty. Chosen at the conservative end. |
| `pace_bias_sigma_mps` | 0.35 m/s | Prior spread absorbing tyre / aero / engine ambiguity. |
| `gap_measurement_sigma_m` | 0.9 m | Own + rival position error of one derived gap sample. |
| `belief_update_interval_s` | 0.5 s | Cadence at which rival observations are consumed (§8, defect 1). |
| `model_residual_sigma_mps` | 0.45 m/s | Irreducible model mismatch; added to every likelihood variance. |
| `dropout_variance_growth_per_s` | 0.35 m²/s⁴ | Widening per second of lost observation. |
| `slots.hysteresis_s` / `slots.hold_s` | 0.15 s / 1.0 s | Identity-slot stability. |

The mode transition matrix is a **hand-authored prior**. `transition_matrix_authorship`
is a required, validated field and `RivalConfig.is_hand_authored` carries it into
the code. Nothing was fitted. Estimating it from synthetic opponent trajectories
is an open follow-up, not a claim this manifest makes.

## 4. Two design decisions worth review

### 4.1 The reported intention posterior is Rao-Blackwellised

Each particle carries a *sampled* mode (driving the nonlinear energy drain, and
scenario rollouts) **and** an analytic `mode_belief` vector. The published
`IntentionWeights` come from the belief, not from counting sampled modes.

This is not cosmetic. An earlier implementation counted sampled modes. Because
`attack` and `defend` have identical likelihoods at zero pressure there is no
restoring force between them, so their sampled marginal random-walks and one is
absorbed. Measured: with 128 particles and 30 s of observations, one seed gave
attack 0.47 / defend 0.49 and another gave attack 0.94 / defend 0.02 — a
confident intention read off Monte Carlo noise. Marginalising analytically fixes
it: the four seeds in `test_observationally_similar_behaviours_stay_ambiguous`
now all give attack ≈ 0.472, defend ≈ 0.487, ratio 0.969, and the analytic
filtering fixed point of the transition prior under equal likelihoods is 0.41 /
0.59 — so the filter is reporting the prior, which is the honest answer.

**Explicit approximation:** each particle's energy trajectory is conditioned on
its sampled mode path while its weight marginalises over modes. That is the
standard mixture-particle-filter trade; it is documented in the module docstring
and is not hidden.

### 4.2 `attack` and `defend` are deliberately unidentifiable from pace

The manifest gives them the same base pace and the same base power. A fast rival
could be attacking the car in front, defending from the car behind, or simply
have different tyres. Only contextual pressure separates them, and
`test_context_pressure_does_not_manufacture_certainty` asserts that even with a
car right behind the rival the two stay within 0.2 of each other.

Command: `./.venv/Scripts/python.exe -m pytest tests/estimation -q -s`

### Own-car estimation — 12 scenarios, 156 records

```

energy RMSE = 4391.2 J, MAE = 3445.7 J (n=156)
speed 90% interval empirical coverage = 0.8782 (137/156)

```

**Nominal 90 % interval, measured empirical coverage: speed 0.8782, progress
0.8654, own energy 0.8974**, each on 156 samples across 12 scenarios (6
model-matched, 6 with an unmodelled driver term), split by scenario.

### Rival energy interval — 12 scenarios, 156 records

```
split=rival-energy-calibration scenarios=12 records=156
rival energy 90% interval empirical coverage = 0.7885 (123/156)
behaviour Brier = 0.7630 (n=156), minimum true-class weight = 0.0394
```

**Nominal 90 % rival-energy quantile interval, measured empirical coverage:
0.7885 on 156 samples.** This is an honest under-coverage and it is reported as
such. The cause is bias, not spread: the filter's mode transition prior is more
active than the fixed mode schedules the generator uses, so the particle cloud
drains faster than the truth in a scenario where the rival simply holds
`normal`. Raising `energy_process_sigma_w` moves coverage 0.63 → 0.74 (45 kW) →
0.76 (70 kW) → 0.81 (100 kW) with diminishing returns, confirming that widening
does not fix a bias. 90 kW was chosen as the conservative end of a defensible
physical range rather than tuned to hit 0.90.

**Consumers must treat the rival energy interval as optimistic at the 90 %
label.** It is a belief propagated through a simplified model from a broad prior,
not a measurement, and it does not currently deliver its nominal coverage.

### Scenario correlation

Measured over four preparation seeds, 64 trajectories each, 20 s horizon at
0.5 s steps: lag-1 autocorrelation of sampled rival energy — mean 0.84, median
0.88, 10th percentile 0.69. The low tail is entirely trajectories pinned against
the empty-battery clip, whose absolute per-step movement is small. Shuffled
control: mean 0.03. Cross-sectional correlation between step *t* and *t+1* across
the ensemble is > 0.97 at every step; worst single-step energy change 5.3 % of the
battery window against a manifest-derived reachable bound of 7.75 %.

### Performance (this machine)

Windows 11 (10.0.26200), Intel64 Family 6 Model 183 (24 logical CPUs), Python
3.12.14, numpy 2.5.3, scipy 1.18.1.

* `update()` with one rival at a 10 Hz decision cadence over a 60 s run:
  **0.834 ms mean** over 600 calls (0.501 s total).
* `sample_scenarios(count=64, horizon=12 s, step=0.5 s)`: **1.105 ms mean** over
  200 calls.

Single-threaded; no profiling or optimisation work was done.

## 7. Known limitations

1. **Rival energy interval under-covers its nominal 90 % label (measured 0.7885).**
   See §5. The cause is a mode-prior bias, not insufficient spread. Do not present
   this interval as a calibrated 90 % interval to an operator.
2. **`predict(estimate, t)` without `state` is approximate, not conservative.**
   The contract transports only marginal standard deviations, so the covariance is
   reconstructed as diagonal; dropping the progress/speed/acceleration cross terms
   can make the propagated uncertainty either wider or narrower than the exact
   propagation. Measured on one case: 2.384 vs 2.415 m/s — i.e. *narrower*. The
   quality is marked degraded and carries a note saying so. Callers holding the
   estimator must pass `state=`.
3. **Time gaps are derived by dividing the distance gap by our own speed** when
   the feed does not publish `gap_ahead_s` / `gap_behind_s` directly. `UNITS_TIME`
   warns this is wrong through corners. The estimator uses it and flags the
   approximation, but it is not a proper common-progress time gap.
4. **Own progress at a rival's observation time is interpolated** from own-car
   progress samples in the same batch (exact for a synchronised feed) and
   otherwise extrapolated at constant speed from the cutoff posterior.
5. **`recharge_spent_this_lap_j` is reported missing** unless a `recharge_ledger_j`
   channel is observed. The CU-K DC-bus ledger is a different bus from the battery,
   and deriving one from the other would violate the separate-ledger rule. This
   means the field is currently always missing on the synthetic feeds.
6. **Coverage was measured on data drawn from the filter's own declared process
   model** for 6 of 12 scenarios. The other 6 add an unmodelled driver term, which
   is why the numbers are not trivially 0.90 — but this is a self-consistency check
   of the linearisation and the noise bookkeeping, not evidence about a real car.
7. **Lateral geometry is always reported unknown** (`lateral_geometry_known=False`).
   Nothing in this module can resolve it, and no contact-risk claim may be built on
   its output.
8. **`sample_scenarios` widening is read off the pace offset, not off energy.**
   Energy is clipped to the legal window, so once part of the ensemble has run flat
   its spread saturates and stops responding to added process noise. The tests and
   `ScenarioEnsemble.energy_spread_at` both document this.
9. **No profiling under load.** The timings in §5 are single-threaded, one rival,
   on one machine. Multi-rival sessions scale linearly in the number of tracked
   cars; that has not been measured.
10. **`predict` propagates rival beliefs by extending the dropout**, so a long
    projection widens the belief but does not model the planner's own influence on
    the rival. That coupling belongs to planning, not estimation.

## 8. Defects found and fixed during this work

1. **The rival likelihood over-counted a 20 Hz feed and understated differencing
   noise.** Differencing two gap samples 50 ms apart, each with ~0.9 m of position
   error, gives a rate whose 1-sigma is ~25 m/s; the filter was charging the
   nominal 0.30 m/s and consuming 20 such "observations" per second. The result was
   a filter that chased position noise: the rival energy interval collapsed from
   3.4 MJ to 0.3 MJ within two seconds and the intention posterior flipped between
   near-certain modes every second, with a measured rival energy coverage of
   **0.1026**. Fixed by (a) charging the real differencing variance
   `2·sigma_gap²/dt²`, (b) forming gap rates over non-overlapping intervals of at
   least `belief_update_interval_s`, and (c) decimating rival observations to that
   cadence in the assembly. Coverage went 0.1026 → 0.7885.
2. **Mode-marginal collapse between degenerate modes** — see §4.1.
3. **The per-mode weight floor was applied and then renormalised**, which left the
   raised mode just *below* its own floor (0.0195 against a 0.02 floor). Replaced
   with an iterated exact redistribution.
4. **`mode_age_s` was reset and then incremented in the same step**, so a particle
   that had just changed mode reported an age of `dt` rather than 0.

## 9. Required integration actions

1. **Coordinator / A02:** pass `IntegrationGapRecord.cumulative_gap_s` for
   `electrical_power_w` into `EstimationContext.integration_gap_s`. Without it the
   energy variance will not widen across a power-channel dropout. The estimator
   applies it once per batch via `OwnCarFilter.apply_integration_gap`.
2. **Coordinator / A02:** pass `QualityAssessment.channels` into
   `EstimationContext.channel_quality`. When present it is used verbatim; when
   absent the estimator derives a coarser per-channel freshness itself.
3. **Coordinator / backend:** publish `EstimatorState.rejected` as a
   `QualityEvent`. It is deliberately absent from `StateEstimate` (§6) but it is
   operationally important — a stream of post-cutoff arrivals means a clock or
   buffering problem.
4. **A06 (planning):** consume `sample_scenarios(belief, count, seed, ...)`.
   `belief` is a `RivalParticleFilter`, reachable as `state.rivals[car_id]`.
   Sampling does not mutate the belief, so repeated planning at one tick sees the
   same opponents. Honour `ScenarioEnsemble.reachable_energy_step_j` when
   interpreting a trajectory.
5. **A06 / A08:** gate every precise energy recommendation on
   `StateEstimate.quality.own_energy_capability`. When it is False,
   `battery_energy_j.value` is `None` and `battery_energy_interval` is a
   `physical_bounds` range — never a point value.
6. **A07 (learning):** `afterlap_core.estimation.calibration` reads privileged
   labels and must stay out of the inference import path. Its
   `split_by_scenario` is available for the shared split machinery;
   `split_by_row` exists only to raise.
7. **Contract proposals:** none. No `handoffs/A05-contract-proposal.md` was
   written; every constraint in `estimate.py` and `quantities.py` was worked with
   as frozen.

## 10. Fixture and source provenance

* Every trajectory used by these tests is generated in
  `tests/estimation/conftest.py` from the declared manifests plus numpy RNG. It is
  labelled synthetic (`SYNTHETIC_NOTICE`) and carries no external data.
* `afterlap_contracts.fixtures` was read for shape compatibility but the tests do
  not depend on it at runtime.
* No import from `afterlap_core.simulation` exists anywhere in
  `packages/core/afterlap_core/estimation/**` or `tests/estimation/**`; the
  simulator-shaped inputs the tests need are defined locally as `OwnTruth` /
  `RivalTruth` / `SyntheticRun`.
* No external dataset, no licensed feed, no third-party model weights. numpy 2.5.3
  (BSD-3-Clause) and pydantic are the only runtime dependencies used here; scipy is
  installed but not imported by this module.
* The synthetic rule-pack figures reused in the manifests (4 MJ battery window,
  350 kW deployment ceiling) come from `configs/scenarios/*.yaml` and are
  themselves declared `synthetic_assumption`.
