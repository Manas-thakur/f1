## Public interfaces

### Adapters

```python
class SourceAdapter(Protocol):           # runtime_checkable
    def capabilities(self) -> SourceCapability: ...
    def open(self, manifest: SessionManifest) -> AdapterOpenResult: ...
    def events(self) -> Iterator[ObservationRecord]: ...
```

`AdapterOpenResult(source_id, state: CapabilityState, capability, detail)` —
`state` is `AVAILABLE` / `DEGRADED` / `UNAVAILABLE`. `open()` never raises for a
missing feed; it reports `UNAVAILABLE` with a reason.

`request_channel(capability, channel) -> CapabilityAnswer` answers a capability
question. `CapabilityAnswer.value` is typed `None` — an unsupported capability
can never return a number.

`public_replay_capability`, `public_replay_mapping`, `team_feed_capability`,
`team_feed_mapping`, `validate_mapping_against_capability`,
`ListObservationSource` (synthetic reference `ObservationSource`).

### The observation-source protocol A03 must satisfy

This is the entire interface between the simulator and ingestion. Implement it
on a *view object*, not on the simulator itself — the adapter must not be able to
reach truth through the object it is given.

```python
from afterlap_core.data import ObservationRecord, ObservationSource

@dataclass(frozen=True, slots=True)
class ObservationRecord:
    source_id: str                 # must equal the adapter's source id
    car_id: str
    source_time_s: float           # source session time, seconds, finite, >= 0
    source_sequence: int           # monotonic within an epoch, >= 0
    fields: Mapping[str, Any]      # vendor field name -> raw value (SI for the simulator)
    received_time_s: float | None = None   # local ingestion clock; defaults to session time
    restart_marker: bool = False   # True on the first record after a sequence reset
    source_time_utc: str | None = None

class ObservationSource(Protocol):
    def observation_capability(self) -> SourceCapability: ...
    def observations(self) -> Iterable[ObservationRecord]: ...
```

Requirements on A03's implementation:

1. `observation_capability().mode` **must** be `SessionMode.SIMULATION`;
   `SimulatorAdapter` refuses anything else.
2. Declare `update_rates_hz` for every channel you actually publish. Quality
   expectations are derived from that declaration, so an undeclared cadence
   makes the channel permanently `DEGRADED`.
3. `fields` keys must be the vendor names in `simulator_mapping()`:
   `speed_mps`, `lap_distance_m`, `progress_m`, `battery_energy_j`,
   `electrical_power_w`, `battery_temperature_k`, `gap_ahead_s`, `gap_behind_s`.
   Any other key is preserved as raw archive data and produces no channel; add a
   mapping entry (and bump `SIMULATOR_MAPPING_REVISION`) to canonicalise it.
4. A field name starting with `truth_`, `hidden_`, `world_`, `gt_`, `oracle_`,
   or named `world_state` / `rival_battery_energy_j` / `rival_energy_j` /
   `opponent_policy` / `rng_state` raises `TruthLeakError` at ingestion.
5. A value that means "not measured" must be `None` (or a sentinel declared in
   the mapping). It must never be `0.0`.
6. On a restart, set `restart_marker=True` on the first record and do not
   re-send source times already emitted; the pipeline refuses them as replays.

`SimulatorAdapter` also accepts a plain iterable or a zero-argument factory of
`ObservationRecord`, so A03 can hand over a generator without defining a class.

### Pipeline

```python
config = SourcePipelineConfig(
    session_id, source_id, mapping, capability, provenance,
    clock=ClockMapping(...), reorder_window_s=0.2, expectations=(),
)
pipeline = IngestionPipeline(config, sequences=..., sink=..., tracker=...)

pipeline.ingest(record, now_s=None) -> PipelineOutput
pipeline.flush(now_s)               -> PipelineOutput   # closes windows on the clock
pipeline.close(now_s=None)          -> PipelineOutput   # drains at end of stream
pipeline.finalise(cutoff_s)         -> None             # publish a decision cutoff
pipeline.heartbeat(at_s)            -> None             # transport liveness only
pipeline.assess_quality(now_s)      -> QualityAssessment
pipeline.stats()                    -> PipelineStats
```

`PipelineOutput(normalised, raw, rejected, channel_quality, integration_gaps)`
supports `+` and `decision_visible()`.

`NormalisedRecord` wraps a `TelemetryEvent` with `session_time_s`, `source_id`,
`mapping_revision`, `raw_packet_id`, `vendor_field`, `labels`, `reason`,
`finalised_before_s`, and the derived `usable_for_decisions` / `out_of_order`.

Labels: `out_of_order`, `excluded_from_finalised_state`,
`late_after_reorder_window`, `backwards_source_clock`,
`out_of_registered_bounds`, `missing_value`, `unmapped_vendor_field`,
`forbidden_vendor_field`.

Individually testable stages: `parse_record`, `validate_structure`,
`SourceClockConverter`, `convert_to_si`, `DeduplicationIndex`, `ReorderBuffer`,
`SequenceAllocator`, `QualityTracker`, `RecordSink` (`MemorySink` /
`TelemetryRecorder`), `PipelineOutput`.

`IngestionRouter` runs several `SourcePipelineConfig`s over **one**
`SequenceAllocator`, which is what makes session sequences unique and monotonic
across interleaved sources.

### Recording

```python
recorder = TelemetryRecorder(root, session_id, mapping_revision=..., chunk_duration_s=10.0)
recorder.append_raw(packet, car_id=..., session_time_s=...)
recorder.append_normalised(record)

recorder.publish(pending)           # atomic manifest update -> now visible
recorder.discard(pending)           # abandon an interrupted import
```

plus `manifest.json` and `acquisition.json`. Raw and canonical are separate
trees; both rows and manifest entries carry `mapping_revision`.

### Backpressure

`CoalescingBuffer[T](capacity, key, name)` — display only; reports
`coalesced_from_sequence` / `coalesced_to_sequence`.
`LosslessBuffer[T](capacity, name=, raise_on_overflow=True)` — raw and decisions;
on overflow it records a visible `RecordingFault` and stops, never drops.

## Design decisions worth reviewing

**Dedup and restart.** The key is `(source_id, epoch, source_sequence)`. A silent
restart replays sequence numbers into the same epoch and is caught as duplicates.
An announced restart advances the epoch — which would make every replayed
sequence look new — so it also arms a *replay guard* at the highest source time
already admitted. Until the source produces something strictly newer than that,
its packets are refused as `restart_replay`. Out-of-order delivery is explicitly
*not* a dedup concern; that is the reorder buffer's job.

**Reorder release rule.** Primary criterion is a session-time watermark
(`max_session_time - window`), which is what actually reorders a burst. The
secondary criterion is an arrival deadline (`arrival + window <= now`), which
guarantees the window closes on the clock and never blocks on a packet that
never arrives. When the deadline fires for a record, everything at or before its
session time is released with it, so a timeout can never emit records out of
session order. A record whose session time is already behind the last released
one has missed the window entirely: it is returned immediately, labelled
`out_of_order` + `late_after_reorder_window`, and archived.

**Freshness.** `QualityTracker.heartbeat()` writes to a field that `assess()`
never reads. Clock uncertainty is added to the observed age before
classification, so it can only make a channel look older. A late (older) arrival
updates counters but does not move `last_session_time_s` backwards, so a late
packet cannot make a channel look fresher.

**Integration gap.** For `electrical_power_w` / `deploy_power_w` /
`harvest_power_w`, a gap longer than 2 expected periods accumulates
`integration_gap_s = elapsed - expected_period`. It is exposed on
`IntegrationGapRecord` (accompanying record), inside `ChannelQuality.reason` as
`integration_gap_s=<seconds>`, and via `QualityAssessment.integration_gap_for()`.
A channel with a nonzero cumulative gap is reported at worst `DEGRADED` even when
its latest sample is fresh. **A05 (estimation) must widen own-car energy
uncertainty by this interval** rather than integrating across the hole.

**Late events vs finalised decisions.** `pipeline.finalise(cutoff_s)` publishes a
decision cutoff. Anything arriving afterwards whose session time is at or before
the cutoff is normalised, archived and recorded, but labelled
`excluded_from_finalised_state`; `usable_for_decisions` is `False` and
`PipelineOutput.decision_visible()` omits it. A cutoff never moves backwards.

## Public-data honesty (source register D01)

`public_replay_capability()` declares exactly one supported channel,
`speed_mps`, at **3.7 Hz**, `clock_error_s=0.5`, and these limitations:

- approximately 3.7 Hz car and location sampling; this source is not a 20 Hz feed
- no battery-energy channel: stored energy is not observable from this source
- lateral placement is not reliable; do not derive `lateral_position_m` or racing line from it
- historical DRS-style fields are not 2026 Overtake eligibility and are left unmapped
- usable for pace, context and calibration only; not an observed energy controller

`public_replay_mapping()` maps only `speed` (km/h -> m/s, sentinel `-1` means
missing). `drs`, `x`, `y`, `z` are **forbidden**: `MappingTable.get("drs")` raises
`MappingError`, and building a table that maps a forbidden field raises at
construction. `n_gear`, `rpm`, `throttle`, `brake`, `date`, `driver_number` are
passthrough and survive verbatim in the raw archive. There is no eligibility
channel in the registry at all — eligibility is A04's state machine, not a
telemetry channel.

## Measured reorder latency

Hardware: Windows 11 (10.0.26200), 24 logical CPUs, CPython 3.12.14 (MSC v.1944,
64-bit), `.venv` in the implementation workspace. Workload: 2000 synthetic
20 Hz packets (2 channels each), every 10th packet delayed by 3 sample periods,
`flush()` driven at each arrival, drained at `now + window`.

| Reorder window | Released | Max induced latency | Mean induced latency | Max buffer depth | Late after close |
|---|---|---|---|---|---|
| 0.00 s | 2000 | 0.0000 s | 0.0000 s | 1 | 0 |
| 0.05 s | 2000 | 0.2500 s | 0.0542 s | 3 | 0 |
| 0.10 s | 2000 | 0.3000 s | 0.1076 s | 4 | 0 |
| 0.20 s | 2000 | 0.3500 s | 0.2092 s | 6 | 0 |
| 0.50 s | 2000 | 0.8000 s | 0.5014 s | 12 | 0 |

Mean induced latency tracks the configured window to within ~1 %, which is the
expected steady-state cost. Max exceeds the window on the tail drain and on the
delayed packets that were held until their predecessor's deadline fired. Ingest
throughput was 17k–22k packets/s single-threaded in the same runs; that number is
an ingestion-loop measurement on synthetic data, not a system latency budget.

The values are reported per source through `PipelineStats.reorder`
(`ReorderStats.as_dict()`), so an operator can see what a chosen window costs
rather than guessing. The measurement script is not committed; reproduce it from
`ReorderStats` or from `test_pipeline.py::test_delayed_burst_...`, which asserts
`max_induced_latency_s ≈ window` for a 0.5 s window.

## Fixture provenance and licence notes

- Every fixture in `tests/data/` is **synthetic**, generated by the test suite,
  and carries `SYNTHETIC_FIXTURE_NOTICE` where it is written to disk. None of it
  is measured telemetry, a real session, or redistributed third-party data.
- `conftest.public_row()` imitates the *shape* of the OpenF1 car-data schema
  (source register D01, https://openf1.org/docs/) — field names `session_time`,
  `date`, `driver_number`, `speed`, `n_gear`, `rpm`, `throttle`, `brake`, `drs`.
  The values are invented. No OpenF1 data is included in this repository and no
  network call is made by any adapter or test.
- `OPENF1_LICENSE_NOTE` is attached to `public_replay_capability().license_note`
  and states that terms review is recorded in the acquisition manifest, not that
  it has been done. `AcquisitionRecord.terms_review_status` must be set by
  whoever actually acquires data; the tests use `review_required`.
- No credential, cookie or token appears anywhere in the module or the fixtures;
  the test secrets are obviously fake strings used only to prove redaction.

## Known limitations and defects

1. **Dedup memory is unbounded per session.** `DeduplicationIndex._seen` keeps
   every admitted `(source, epoch, sequence)`. Fine for a race-length session;
   a long-lived process needs a windowed or Bloom-filter variant.
2. **The reorder window can still emit out of order across very wide gaps.** If a
   packet is delayed by more than the configured window *and* a later packet's
   deadline fires first, the late packet is labelled `out_of_order` rather than
   reordered. That is the intended bound, not a bug, but the window has to be
   chosen against a source's real jitter.
3. **`PublicReplayAdapter` reads the whole archive into memory** (`_rows()`).
   Acceptable for a session-sized file; a large multi-session archive needs a
   streaming Parquet reader.
4. **Chunk manifests are rewritten in full on every publish.** Atomic and simple,
   but O(chunks) per flush. Fine at the tested scale; revisit if a session
   produces thousands of chunks.
5. **The recorder is single-writer.** Two `TelemetryRecorder` instances on the
   same session directory would clobber each other's manifest. A multi-writer
   session needs a manifest lock or per-writer manifests merged by a reader.
6. **`TeamFeedAdapter` has no transport.** With a fully authorised
   `TeamFeedAuthorisation` it deliberately raises `FeedUnavailableError` rather
   than emitting placeholder data. That is the honest behaviour until reviewed
   field definitions exist; it also means the "authorised" path is untested
   against a real feed.
7. **`electrical_power_w` sign convention.** The registry documents it as signed
   (positive deploys, negative harvests). Ingestion does not enforce a sign, and
   the registry declares no bounds for that channel, so a mis-signed vendor field
   would pass. Bounds should be added to the registry if that matters.
8. **`ReplaySession` holds all records in memory**, sorted once. Chunked
   streaming replay is not implemented.
9. Hypothesis property tests run 40 examples each; they are fast but not
   exhaustive.
