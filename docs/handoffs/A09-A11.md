## 2. What each route does, and what it refuses to do

### 2.1 Engineer console

Information order: the shell strip (mode, session, car, lap, flag, data age,
source quality) is A12's; then the decision, the energy consequence, speed and
gap, the battle, the immutable timeline, and a sources panel. One cursor drives
every trace panel — `view.cursorValue` in the shared store, so moving it in the
energy panel moves the speed and gap panels and the replay route too.

**The fourteen states** the specification names are derived by one pure
function, `deriveConsoleStatus` in `lifecycle.ts`. It returns two axes plus a
single headline, because "the feed is stale" and "the planner timed out" can be
true at once and a stale-source warning is explicitly independent of the
connection:

- feed: `disconnected`, `connecting`, `healthy`, `degraded`, `stale`
- advice: `missing-energy`, `solver-timeout`, `no-feasible-plan`,
  `rule-unknown`, `no-recommendation`, `selected-pending`, `executing`,
  `completed`, `expired`, plus `active` for a live proposal
- headline: whichever of the fourteen the banner shows

All fourteen are reached and asserted from typed fixtures in
`lifecycle.test.ts` (26 tests).

**Interaction.** `select`, `mark_communicated` and `reject` are three separate
`POST /sessions/{id}/recommendations/{rid}/actions` calls through A12's
`runCommand`, each with an `Idempotency-Key` and `expected_revision`. Execution
observation is not an operator action at all: it arrives as
`execution_observed` on the stream, or as the response to a simulator driver
action.

- **Nothing is optimistically marked selected.** On success the console
  re-reads the authoritative snapshot; it never writes a status into the store,
  and the store has no action that would let it. Asserted with a blocked
  request in `EngineerConsole.test.tsx`.
- **A command in flight blocks a duplicate.** The button goes to `pending` and
  `beginRequest` refuses the second submission.
- **A 409 refreshes the evidence and never retries.** One send, one snapshot
  re-read, the decision query invalidated, the recommendation status untouched.
- **A local expiry clears the selectable action immediately** and says the
  server has not yet published the new status. It does not rewrite
  `recommendation.status`.
- **`quality_changed` disables time-sensitive actions immediately**, through
  A12's `selectTimeSensitiveActionsEnabled`, with its reason as the button's
  `disabledReason`.
- **A rule invalidation clears the action**, because A12's reducer sets the
  status to `invalidated` on `rule_context_changed` and the derivation treats
  that as terminal.

**Mobile** (`max-width: 768px`) renders a read-only summary: the decision, its
trigger, end condition, validity and operator status, with every command
disabled and a notice saying why. Laboratory controls never appear on this
route at any width.

**Evidence inspector**: a real dialog with a title, a close control, Escape
handling and focus restoration to `#engineer-open-evidence`. It shows the
observed state revision, the independent rule checks with their sources and
margins, the unresolved conditions, the predicted checkpoint outcomes, the
event forecasts with their calibration status, and the rule context.

### 2.2 Simulation lab

- **Scenario configuration** offers exactly the fields `POST /sessions`
  accepts. Validation runs before anything starts: mode must be `simulation`,
  the scenario id must be an identifier, the rule pack must resolve through
  `GET /rulesets/{id}`, the seed must be a non-negative integer, a named model
  bundle must be listed by `GET /models`. Every shipped rule pack declares
  `reviewed: false`, so the form **blocks the start until the operator
  acknowledges the synthetic and unreviewed inputs**, and never relabels them.
- **Initial progress, gap and energy, opponent policy, channel delay and
  missing-channel injection are not offered.** `CreateSessionRequest` carries no
  such fields; they belong to the scenario document the server resolves. The
  fieldset is disabled and says exactly that, and points at the two shipped
  scenarios that already exercise degraded observation
  (`loop-no-energy-channel`, `loop-regen-disabled`). Collecting values that
  would be silently discarded would have been the dishonest option.
- **Run control** issues real `start/pause/resume/step/stop` commands with the
  expected revision. **Speed changes wall-clock pacing only**: it sets the
  interval at which an optional auto-advance toggle issues one `step`, and the
  simulated seconds per step is a separate field. `pacingIntervalMs` is
  unit-tested. Run control is disabled for a non-simulation session with the
  reason that pausing a live-team session would pause acquisition.
- **Snapshot** posts to `/sessions/{id}/snapshots` and shows the returned
  `snapshot_id`, `snapshot_hash` and session time.
- **Compare from here** launches one `POST /experiments` from a single
  snapshot with a reference and a candidate treatment and **the same seed list
  on both**, which is what pairs them. It refuses a candidate identical to the
  reference. The alignment axis (common progress or common elapsed time) is a
  labelled control that writes the shared `cursorAxis`, and every comparison
  states which one is on screen.
- **Branch outcomes are `unmeasured`, not zero**, with the reason: the control
  plane returns a server-side file path for a report and no route serves the
  body (§6.1).
- **Experiment jobs** list status, progress, partial-result labelling and the
  failure detail. A cancelled job with progress reads `cancelled` +
  `incomplete`. Seed count, scenario family and evaluator revision are shown
  for jobs this browser submitted and read `not available` with the reason for
  any other, because `ExperimentStatusResponse` carries a manifest hash, not the
  manifest.

### 2.3 Replay

Aligned traces on the one shared cursor — A12's `ChartFrame` and the store's
cursor, not a second chart-event protocol. The alignment axis is stated on
every panel and on a badge. A series whose `x_coordinate` differs from the
selected alignment is drawn on its own coordinate and labelled, because
re-indexing it without a mapping would invent samples.

**Snapshot restore is disabled, with the exact reason.** `SessionCommandKind`
is `start | pause | resume | stop | step`: there is no seek command, and no
route lists or restores a session snapshot. The cursor is a view position and
changes no server state. A live-team session gets the different reason: it
cannot seek its authoritative clock.

### 2.4 Driver display

Dark and high-contrast through A12's `.afterlap-driver-scope` token block, which
nothing else in the product uses. One primary instruction, its trigger, its end
checkpoint, the energy-target status, and mode/eligibility in a stable context
row. Large tabular numerals for speed, stored energy, bus power and lap
distance. No probability, no chat, no scrolling telemetry, no paragraph — all
four asserted.

Precedence, in `precedence.ts`:
`mode-not-permitted > safety > withdrawn > stale > instruction > completed > neutral`.

- **A pending engineer selection is not approved advice.** The instruction is
  shown only for a server-recorded `selected`, `communicated` or `executing`.
  A `proposed` recommendation, including one with a select in flight, shows
  `NO INSTRUCTION`.
- **A local watchdog clears the instruction** if no stream update lands inside
  its window (5 s in production, injectable for tests). It is independent of
  any server message: a heartbeat proves a connection exists, not that data is
  fresh.
- **Disconnection keeps only aged static context**, explicitly labelled with its
  age, and never an imperative.
- **Simulator input** posts `POST /sessions/{id}/simulator/driver-action` with
  the profile, the session time and the recommendation id. Profiles come from
  the resolved `admissible_profiles`; an empty set disables them with a reason.
  A non-simulation session disables them with the mode reason, and the server
  refuses regardless. Choosing a profile is labelled as reporting an execution,
  not as acknowledging the instruction.
- Every state carries a geometric mark and a word as well as a border colour.

### 2.5 Evidence, rules, models

- `/experiments/:id/report` reads the job from `GET /experiments/{id}` and the
  bundle A13 writes. **The four learned comparison rows render as
  `unavailable` with the report's own reasons**, and the page states that no
  win rate, success percentage or aggregate score is computed here — the report
  deliberately contains none. A malformed body renders the same named
  unavailable state as an absent one.
- `/rulesets/:id` shows the applicable limits converted through the channel
  registry, per-concern coverage with source links, test ids and reviewer, and
  the unsupported conditions with what they do to advice. An article number is
  labelled as recording where a transcription would come from, not as evidence
  that it happened.
- `/models` distinguishes candidate from approved by referenced benchmark
  evidence, flags an `approved` bundle with no `benchmark_report_hash` as a
  record the evidence does not support, and offers **no promotion control** —
  no promotion route exists, and a button that did nothing would be a false
  claim about the system.

## 5. Which states come from fixtures and which from a live backend

**None came from a live backend. There is no running server in this workspace.**
Every REST response in the unit tests is served by the real `ApiClient` /
`LabClient` over a stubbed `fetch`, so the header contract, the request bodies
and the typed-error decoding are exercised; every REST response in the browser
tests is served by Playwright route interception; the WebSocket is served by
`page.routeWebSocket` and, in unit tests, by an injected fake socket.

| State | How it is reached here | Needs a live backend to confirm |
|---|---|---|
| healthy, degraded, stale, no-recommendation, selected-pending, executing, completed, expired, missing-energy, solver-timeout, no-feasible-plan, rule-unknown | typed fixtures | no — these are pure derivations of contract objects |
| disconnected, connecting | injected socket / mocked socket | partly: real reconnect timing and the server's bounded replay buffer |
| sequence gap → resync | a crafted envelope | **yes** — against a real bounded buffer and a real `resync_required` |
| wrong-session rejection | `foreignEnvelope` fixture | no |
| 409 stale revision, 422 expiry | mocked typed errors | **yes** — that the server really returns these codes for these races |
| lease acquisition and `lease_not_held` | not exercised | **yes** — see integration action 4 |
| driver-action refusal for a non-simulation session | client-side refusal asserted | **yes** — the 403 is server-side and untested here |
| experiment progress over the stream | not exercised | **yes** |
| a real benchmark report body | fixture shaped like `ReportBundle.as_dict()` | **yes** — no route serves one (§6.1) |

## 6. Known limitations

1. **No route serves a benchmark report body.** `GET /experiments/{id}`
   returns `report_path`, a server-side filesystem path a browser cannot read,
   and nothing serves the JSON A13 writes under `artifacts/reports/`. The
   evidence route calls `GET /experiments/{id}/report` — **a route that does
   not exist today** — and renders a named unavailable state naming the missing
   route when it 404s. Nothing is substituted for it. See integration action 1.
2. **No route lists or restores a session snapshot, and there is no seek
   command.** Replay's restore control is present and disabled with that exact
   reason; the lab lists only the snapshots it created in the current view.
3. **`POST /sessions` cannot express initial conditions or observation
   conditions.** The lab's robustness controls are therefore a disabled,
   explained fieldset rather than inputs.
4. **`ExperimentStatusResponse` returns a manifest hash, not the manifest**, so
   seed count, scenario family and evaluator revision are unavailable for any
   job this browser did not submit.
5. **No authentication exists.** Every command is sent as
   `operator_id: "console-operator"`, stated on screen. No control lease is
   acquired before commanding: the server's `require_lease` will reject if a
   lease is enforced, and the console surfaces `lease_not_held` as a typed
   error rather than silently retrying. Acquiring and renewing the lease is
   integration action 4.
6. **The bundle grew from 417 kB to 903 kB raw** (138 → 237 kB gzipped),
   almost entirely `schemas.json`, which became reachable because every feature
   route now opens a session stream. A12 anticipated this. A lazy-load patch is
   written out in the shared-patch handoff and deliberately **not applied**,
   because it changes an A12-owned module's failure mode and needs its own test.
7. **Plot shape is unverified.** The canvas assertions read painted tick text,
   magnitude and placement. They compare no pixels, so a wrong trace colour, a
   wrong line shape or an inverted series would still pass. That is A12's
   standing limitation and it applies to these panels too.
8. **The auto-advance toggle is not exercised in a browser.** It is off by
   default; `pacingIntervalMs` is unit-tested but the loop that uses it has
   only been run by hand.
9. **No human factors study.** No claim is made about recognition time or
   about missed or incorrect mode selection on the driver display. The
   specification requires such a study before any usability performance claim
   and none has been done.
10. **The gap panel is usually empty.** Nothing in the shipped stream publishes
    `gap_ahead_s` as a telemetry view, so the panel renders its named empty
    state outside the mocked suite. That is correct behaviour, not a bug, but it
    means the panel's populated appearance is only seen against fixtures.
11. **`prefers-reduced-motion` and compact density** are inherited from A12's
    tokens and were not re-verified per route.
12. **A12's `src/app/routes.test.tsx` was edited.** It asserted that these
    seven routes were placeholders. The change is itemised in
    `handoffs/A09-A11-shared-patch.md` §3.

## 9. What this does not establish

Seven routes render, obey their contracts and are accessible at seven widths
with zero serious or critical axe violations. That is all.

Nothing here measures decision quality, simulator fidelity, rule coverage,
model performance or human factors. Every number on screen came from a fixture
or from a contract object a mocked server returned. The unavailable states are
the honest part of this module: there are a lot of them, each names a specific
missing artefact or missing route, and not one of them is a zero.
