# Model registry and reproducibility guide

Every model in this repository, how it was built, what was actually measured,
and what is still only a target. Prepared alongside the connected-runtime work;
regenerate the machine-readable half with

```
uv run python -m afterlap_core.cli model-registry --output artifacts/reports/model_registry.json
```

The JSON is derived from the code and the frozen configuration documents, so
the tables below cannot drift from what would run.
`tests/operations/test_model_registry.py` fails if this document names a model
the registry does not have, or quotes a parameter count the generator does not
produce.

**Everything here is synthetic.** Every configuration behind every model is an
engineering assumption. Nothing in this document is a measurement of a real
car, a real circuit or a real race, and nothing is a regulatory or safety
claim.

## How to read the numbers

Three kinds of statement appear below and they are never mixed.

| Kind | What it means | Example |
|---|---|---|
| **Architecture** | Something that exists in the code right now | 116,228 trainable parameters |
| **Observed** | A value a specific bounded run actually produced | actor loss mean +37.7447 over 500 samples |
| **Target gate** | A threshold that must be met before promotion, and has not been | benefit ≥ 2.0 utility over `mpc_only` |

An observed value always names the run that produced it. A target gate is never
reported as an achievement.

## `sac-energy-strategy`

| | |
|---|---|
| Purpose | Propose a bounded soft energy preference that warm-starts the constrained solve |
| Module | `afterlap_core.learning.train_sac` |
| Algorithm | Soft Actor-Critic, stable-baselines3 `MlpPolicy`, used unmodified |
| Inputs | 192-value `energy-v1` observation |
| Outputs | 2 bounded preferences in [-1, 1]: deployment budget and reserve target |
| Loss | The library's actor, critic and entropy objectives |
| Config | `configs/learning/sac-v1.yaml`, `sha256:ce8159043936cc6e7…` |

### Architecture

| Network | Layers | Parameters | Updated by |
|---|---|---:|---|
| actor | 192→256→256, `mu` and `log_std` heads | **116,228** | optimiser |
| critic | twin Q, 194→256→256→1 each | **231,938** | optimiser |
| critic target | same shape as the critic | 231,938 | Polyak average |
| entropy coefficient | scalar | 1 | optimiser |

**Optimiser-updated total: 348,166** (+1 entropy scalar). The naive sum across
all three networks is 580,104, which counts the critic twice: Stable-Baselines3
2.9.0 leaves `requires_grad=True` on the target copy while building the
optimiser over `critic.parameters()` alone. The registry reports the actor count
for the shipped configuration; a packaged bundle reports all of them, read off
its own constructed modules, in its hash-covered `training_report.json`.

### Training data

There is no dataset file. Transitions are generated by the simulator-backed
Gymnasium environment, so a bundle hashes the *generator*: environment
configuration, scenario selection, seeds, reward revision and step budget. The
manifest says so in those words rather than implying a stored corpus.

Split: `configs/learning/circuit-split-v1.yaml`. The held-out circuit group
cannot be sampled today — four of six circuits are below `geometry_validated`
and the calibration group is a single circuit.

## `continuation-return-ensemble`

| | |
|---|---|
| Purpose | Predict the ordinary discounted continuation return beyond the planner's horizon |
| Module | `afterlap_core.learning.value` |
| Algorithm | 5 independently initialised MLPs, 192→256→256→1, ReLU |
| Outputs | one value in objective utility units, plus the ensemble disagreement |
| Loss | weighted Huber (δ = 1.0) on standardised targets, Adam, early stopping |
| Config | `configs/learning/value-v1.yaml`, `sha256:95e8806674076892e…` |

**115,457 parameters per member; 577,285 across the five.** These are *not* a
soft value function and not a race time in seconds: the label is the ordinary
discounted return, with no SAC entropy term.

### Training data and split

Per-cutoff returns from complete simulator episodes under one named frozen
controller. The split is **by episode, never by row** — adjacent cutoffs of one
episode are the same trajectory. `fit_ensemble` refuses incomplete episodes
outright, and refuses to fit on fewer than two.

### Serving and limitations

`value-v1` declares `frozen_before_final_test: false`, so the support gate
disables the contribution **regardless of fit quality**. The shipped thresholds
are declared placeholders, not derived from a calibration set. An ensemble
fitted under one controller is not a universal value function.

Fallback: the planner's analytic terminal energy term.

## `probability-calibrator`

| | |
|---|---|
| Purpose | Map a raw rollout-ensemble frequency to a calibrated probability |
| Module | `afterlap_core.learning.calibration` |
| Algorithm | isotonic regression by pool-adjacent-violators, one map per event |
| Parameters | non-parametric: a step function whose knot count depends on the data |

Monotonicity is an operational requirement, not an aesthetic one: the planner
ranks candidates partly by these probabilities, so a calibration step that could
reorder two forecasts would change the recommendation for reasons unrelated to
evidence.

### Observed — no calibrator was fitted, and that is correct

Two 40-episode collections with re-simulation enabled and the planner deadline
raised to 5.0 s (`artifacts/reports/calibration_fit_seed0.json`,
`calibration_fit_random_seed7.json`):

| Collection | Episodes | Forecasts | Labelled | Dropped | Base rate, all four events |
|---|---|---|---|---|---|
| `held-neutral/action-zero`, seed 0 | 40 | 1,296 | 1,296 | 0 | 0.0 |
| `uniform-random/seed7`, seed 7 | 40 | 688 | 648 | 40 | 0.0 |

In this scenario the ego car never passes the rival and is never ahead at a
checkpoint, under either controller. A single-class set cannot identify a
monotone map and a constant fit would report a perfect Brier score, so each
event was refused with that reason and the probabilities stay published as
uncalibrated raw frequencies.

The unit test fits a *known* distortion (a forecaster whose stated frequency is
the square of the truth) and confirms the held-out Brier score improves from
0.2062 to 0.1944, so the fitter itself is exercised.

### A forecaster defect this surfaced

`ahead_at` is forecast at 1.0 in 7 of 32 probe cases and realised 0 in all 32.
`rollout.py` evaluates it over the branch horizon, where a rival that has not
crossed yet makes the forecast declare us ahead; a realisation resolves it over
the whole episode. Same words, different windows. Recorded in full at
`artifacts/reports/finding_ahead_at_horizon.md`; **not fixed**, because it
changes an event definition the specification states.

Fallback: the uncalibrated raw frequency, labelled as such.

## The models nobody trained

| Model | Module | Why it is here |
|---|---|---|
| `planner-surrogate` | `afterlap_core.planning.surrogate` | The smooth reduced model the solver differentiates. Closed-form arithmetic; every coefficient is `verification: synthetic_assumption`. The harvest-opportunity coefficient is declared the largest single source of surrogate/simulator disagreement. |
| `rollout-forecaster` | `afterlap_core.planning.rollout` | Weighted Monte-Carlo over sampled rival hypotheses with rivals re-deciding. Produces the frequencies the calibrator would calibrate and the ranges the recommendation publishes. |
| `own-car-estimator` | `afterlap_core.estimation.own_car` | EKF with a hand-written, difference-checked Jacobian. Its output is the only path from the world to the controller. |
| `rival-belief` | `afterlap_core.estimation.rivals` | Mode-weighted filtering over declared rival behaviours. Rival stored energy can never be labelled measured; the nominal 0.90 quantile label measured 0.7885 coverage. |
| `independent-rules-checker` | `afterlap_core.rules.checker` | Seven named limit checks. Aggregate is fail > unknown > pass, and **unknown is not acceptance**. Its verdict is final. |
| `reward-objective` | `afterlap_core.learning.reward` | Frozen coefficients plus potential-based shaping. A missing coefficient raises rather than defaulting. |

## Reproducing all of it

Identical in PowerShell, bash and zsh. Run from the repository root; never call
the virtualenv interpreter directly.

### Install

```
uv sync --frozen --all-packages --group learning --group solver --group data
bun install --frozen-lockfile
```

`learning` pulls torch, gymnasium, stable-baselines3 and tensorboard; `solver`
pulls CasADi. Both are optional extras and neither is installed by CI, so the
learning and solver suites run locally only.

### Check the environment

```
uv run python -m afterlap_core.cli doctor
```

### Measure throughput before choosing a budget

```
uv run python -m afterlap_core.cli throughput --transitions 1000
```

### Train, evaluate deterministically, and package

```
uv run python -m afterlap_core.cli train --smoke --total-steps 900 --package
uv run python -m afterlap_core.cli train --total-steps 20000 --seed 11 --n-envs 4 --checkpoint-every 5000 --evaluation-episodes 3 --package --output artifacts/reports/bounded_train_seed11.json
uv run python -m afterlap_core.cli package-model --checkpoint artifacts/models/learning/<run-id>/checkpoints/final
```

A smoke run is labelled a smoke run in the bundle id, the training status, the
limitations and the machine-readable report.

### Fit the prediction models

```
uv run python -m afterlap_core.cli fit-value --episodes 20 --seed 0 --scenario two-straight-counterattack --output artifacts/reports/value_fit_seed0.json
uv run python -m afterlap_core.cli fit-calibration --episodes 40 --seed 0 --scenario two-straight-counterattack --planner-deadline-s 5.0 --output artifacts/reports/calibration_fit_seed0.json
```

`fit-calibration` enables re-simulation, which changes the environment revision,
and raises the deadline so the ensemble can finish. Both values are recorded on
the report. Collecting only the decisions that fit the operational 200 ms budget
would keep a biased sample of the easy cases.

### Benchmark, ablate and ask about promotion

```
uv run python -m afterlap_core.cli evaluate --candidate baseline --benchmark commissioning-smoke
uv run python -m afterlap_core.cli ablate --candidate mpc_plus_actor --disable policy
uv run python -m afterlap_core.cli promote --bundle artifacts/models/bundles/<run-id>
```

`promote` reads and decides; it writes nothing. Recording approval as a side
effect of asking whether the gates pass would be the automatic promotion
`AGENTS.md` forbids, so the decision carries `recorded_on_disk: false`.

### Regenerate this registry

```
uv run python -m afterlap_core.cli model-registry --markdown
uv run python -m afterlap_core.cli model-registry --output artifacts/reports/model_registry.json
```

### Gates

```
uv run ruff format --check .
uv run ruff check .
uv run mypy
uv run python scripts/check_no_comments.py
uv run python docs/tools/validate_package.py
uv run python -m afterlap_contracts.schema_export --check
uv run pytest -q -m "not slow" --ignore=tests/learning
uv run pytest -q tests/learning tests/evaluation
bun run lint
bun run typecheck
bun run test
bun run build
```

On Windows, `bun run build` fails at the Next.js standalone tracing step with
`EPERM: operation not permitted, symlink` unless developer mode is enabled;
compilation, type-checking and static generation all succeed first, and CI
builds on Linux.

## What a promotion-quality model would need

Nothing in this repository is close, and the gap is a budget gap rather than a
machinery gap. From `configs/benchmarks/promotion.yaml`:

1. **At least 100 independent test scenarios.** The shipped held-out manifest
   declares 25 and says so at `held-out-test-v1.yaml:23-30`.
2. **At least 5 training seeds.** `sac-v1.yaml` declares five; one has been run.
3. **A measured `mpc_only` baseline** to compare against. The controller now
   exists and is runnable; the comparison has not been run.
4. **A hierarchical paired bootstrap** whose interval excludes zero at a benefit
   of at least 2.0 utility.
5. **Two named ablations**, which are now measurable because each learned row
   implements `without_contribution`.
6. **A withdrawal rate at or below 0.05.** The bounded run observed 0.6636.
7. **Frozen support thresholds** in `value-v1` and a frozen calibrator, neither
   of which exists.
8. **A training budget the hardware can reach.** At 8.28 transitions/s the
   declared 200,000-step budget is about 6.7 hours per seed of environment time
   alone, so five seeds is well over a day on this machine before any
   evaluation.
